The problem it solves

Every bookkeeper loses the first hours of every new client to the same job: the client's file doesn't import. Dates in three formats, amounts stored as text, non-breaking spaces breaking the parser, debit and credit split across two columns, duplicate rows — and the expensive one, a running-balance column that doesn't reconcile.

Generic cleaners make this worse for accounting work because they guess. A guessed date or a silently imputed amount is a restatement waiting to happen.

The four contracts

  1. Never invents a value. Unrepairable cells are written through byte-identical and escalated with a machine-readable reason.
  2. Every change is recorded and reversible. The audit stores the exact original for every changed cell.
  3. Ambiguity is escalated, not guessed. 01/02/2026 and 1,23 are escalated unless the operator explicitly opts in.
  4. The balance chain is verified. Every consecutive pair is checked; breaks are reported with line number and exact discrepancy.

Usage

python3 ledger_rescue.py client_statement.csv \
    --out ./out --date-order dmy --opening-balance 950.00
OutputWhat it is
out/clean.csvimportable data — ISO dates, signed amounts, integer-cent exact
out/escalations.csvevery cell a human must look at, with reason codes
out/audit.jsonfull dossier: changes, drops, header mapping, balance chain

Money is carried in integer cents end to end. No floats touch an amount. Stdlib only — reads and writes only inside the paths you give it.
